# 销售线索跟进系统技术方案

## 1. 方案说明

本文档基于 `doc/销售线索跟进系统PRD.md` 的 2026-06-05 版本编写，技术方案先拆成 S1 最小可跑闭环和 S2+ 后续规划。S1 只交付业务闭环所需的最小集合：本地服务可启动、用户可在界面中操作、能走完线索创建、跟进记录、状态流转、提醒查看和主管风险看板。

AI 跟进建议、老板看板、移动端完整适配、数据导出、更多筛选统计和运营配置统一放入 S2+。自动分配规则、公海池、复杂 CRM 商机、报价、合同、回款、市场投放 ROI、自动触达和多租户计费不纳入 S1。

## 2. 建设目标与范围

### 2.1 S1 建设目标

- 本地服务启动后，用户可以通过浏览器进入可操作界面。
- 用户可以选择或登录为销售、主管两类演示角色。
- 销售可以创建线索、查看本人线索、记录跟进、设置下次联系时间。
- 销售首页可以清晰回答“今天该跟谁”，展示今日待联系和已逾期线索。
- 线索状态按固定状态机流转，并记录每次状态变更。
- 主管可以查看团队今日待联系、即将到期和已逾期线索。
- 浏览器侧按销售、主管两层角色做 S1 演示数据隔离；S2+ 接真实后端时再做接口鉴权。
- S1 不追求完整移动端适配，但核心页面需要在窄屏下可基本操作。

### 2.2 S1 核心操作动线

```text
启动本地服务
  -> 进入登录/演示角色选择页
  -> 以销售身份新建线索
  -> 在线索详情新增跟进记录并设置下次联系时间
  -> 在线索详情将状态从新线索流转到已联系/有意向/已成交或已丢失
  -> 回到销售首页查看今日待联系和逾期线索
  -> 切换主管身份查看团队风险看板
```

S1 只要这条动线可以在 UI 中跑通，即视为业务最小闭环成立。

### 2.3 版本范围

| 版本 | 范围 | 技术处理 |
| --- | --- | --- |
| S1 / MVP | 本地可启动 UI、演示角色、线索 CRUD、跟进记录、状态流转、今日待联系、逾期提醒、主管风险看板、基础权限 | 本方案详细设计 |
| S2+ | 老板看板、AI 跟进建议、移动端完整适配、数据导出、转化率、高级筛选、近 7 天/30 天活跃度统计、运营配置 | 仅保留规划和扩展点，不阻塞 S1 |

## 3. 总体架构

### 3.1 架构概览

S1 采用零依赖本地 Web 应用，以本地可启动、界面可操作、闭环可演示为优先目标。Node 只提供静态文件服务；页面渲染、交互、表单校验、业务规则、状态机、权限范围模拟和基础统计都在浏览器侧完成；数据写入 `localStorage`，不引入数据库和后端 API。

```text
浏览器 / 窄屏浏览器
        |
        v
Node 静态文件服务
        |
        v
原生 HTML / CSS / JavaScript
        |
        v
localStorage
```

S2+ 引入 AI 跟进建议后，可增加独立的 AI Suggestion Service：

```text
线索详情页
   |
   v
后端 API 服务 ---- AI Suggestion Service ---- 大模型服务
   |
   v
线索与跟进记录数据
```

### 3.2 前端模块

S1 前端模块：

- 登录/演示角色选择页。
- 销售首页，展示今日待联系和逾期线索。
- 线索列表，支持新建、搜索和按状态筛选。
- 线索详情，展示基础信息、跟进时间线和状态变更记录。
- 新增跟进记录弹窗或页面。
- 状态流转操作。
- 主管风险看板，展示团队今日待联系、即将到期和已逾期线索。

S2+ 前端模块：

- 老板看板。
- AI 跟进建议入口和结果展示。
- 移动端快速跟进页面。
- 数据导出和高级筛选统计页面。

S1 的入口隐藏和交互约束用于本地演示，不等同于真实安全边界。S2+ 接真实后端时，所有数据权限必须以 API 服务校验为准。

### 3.3 后端模块

S1 本地服务与领域模块：

- StaticServer：Node 静态文件服务，负责启动本地 UI。
- DemoUserService：演示角色识别、销售/主管切换、数据范围计算。
- LeadStore：线索创建、编辑、查询、状态流转。
- FollowUpStore：跟进记录创建、查询、同步更新线索关键时间。
- ReminderSelector：今日待联系、即将到期、逾期线索计算。
- DashboardSelector：主管风险看板和最小状态数量统计。
- LocalStorageAdapter：浏览器本地持久化。

S2+ 后端模块：

- BossDashboardService：老板看板、公司级漏斗和趋势。
- AiSuggestionService：AI 跟进建议。
- ExportService：数据导出。
- AdvancedReportService：转化率、近 7 天/30 天活跃度和高级筛选统计。

## 4. 核心领域模型

### 4.1 线索状态机

状态定义：

| 状态 | 说明 | 是否终态 |
| --- | --- | --- |
| 新线索 | 刚录入，尚未完成首次有效联系 | 否 |
| 已联系 | 已与客户发生一次有效沟通 | 否 |
| 有意向 | 客户表达明确需求或后续沟通意愿 | 否 |
| 已成交 | 线索完成成交 | 是 |
| 已丢失 | 确认不再继续跟进 | 是 |

允许流转：

```text
新线索 -> 已联系 -> 有意向 -> 已成交
  |          |          |
  v          v          v
已丢失     已丢失     已丢失
```

状态规则：

- 新线索可流转为已联系、已丢失。
- 已联系可流转为有意向、已丢失。
- 有意向可流转为已成交、已丢失。
- 已成交和已丢失为终态，不进入待联系和逾期提醒。
- 每次状态变更必须写入状态日志。
- 状态变更为已丢失时，必须填写丢失原因。

### 4.2 丢失原因

丢失原因枚举：

- 无需求。
- 预算不足。
- 已选择竞争对手。
- 联系不上。
- 决策周期过长。
- 信息无效。
- 其他。

## 5. 核心业务流程

### 5.1 S1 销售录入并跟进线索

1. 销售新建线索，填写客户名、联系人、来源、备注等字段。
2. 系统自动将线索归属当前销售，并写入 `owner_id` 和 `team_id`。
3. 线索初始状态为新线索。
4. 销售新增首次跟进记录。
5. 系统强制要求填写下次联系时间。
6. 后端在同一事务中写入跟进记录，并更新线索的最近跟进时间和下次联系时间。

### 5.2 S1 销售处理今日待联系

1. 销售进入销售首页。
2. 系统查询下次联系日期为今天、且状态不是已成交或已丢失的线索。
3. 今日待联系按下次联系时间升序排序。
4. 已逾期线索从今日待联系中排除，单独展示在逾期列表。
5. 销售点击线索进入详情，新增跟进记录并设置新的下次联系时间。

### 5.3 S1 主管查看团队风险

1. 主管进入主管看板。
2. 系统基于主管的团队范围查询今日待联系、即将到期和已逾期线索。
3. 看板按销售人分组展示今日待联系数量、即将到期数量、逾期数量和明细。
4. 每条线索展示客户名、状态、下次联系时间、距到期时间或逾期天数、最近跟进摘要。
5. 主管可按销售人、状态、到期状态、逾期天数筛选。

### 5.4 S2+ 老板查看公司销售过程

1. 老板进入老板看板。
2. 系统查询全公司线索汇总数据。
3. 展示状态分布、转化漏斗、近 7 天和近 30 天新增线索数、跟进记录数。
4. 支持按团队或主管筛选。

### 5.5 S2+ AI 跟进建议流程

1. 销售在线索详情页点击 AI 跟进建议。
2. 后端读取线索基础信息、当前状态、备注、全部跟进记录摘要、最近跟进时间和下次联系时间。
3. 后端组装提示词，调用大模型服务。
4. AI 返回沟通时机、切入话题、准备材料和风险提示。
5. 前端展示建议，并允许销售复制文本。
6. AI 生成失败时展示降级提示，不影响线索详情和新增跟进。

## 6. 功能模块设计

### 6.1 S1 销售首页

销售首页核心回答“今天该跟谁”。

功能：

- 今日待联系线索列表。
- 已逾期线索列表，并标识逾期天数。
- 今日待联系按下次联系时间升序排列。
- 点击线索进入详情页。
- 快捷新增跟进记录。
- 本人线索状态数量概览，S1 只展示当前全量状态数量。

关键规则：

- 今日待联系：下次联系日期等于今天，且状态不是已成交、已丢失。
- 逾期线索：下次联系时间早于当前时间，且状态不是已成交、已丢失。
- 同一条线索如果已逾期，不再重复出现在今日待联系中。

### 6.2 S1 线索管理

新建线索字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 客户名 | string | 是 | 公司或客户主体名称 |
| 联系人 | string | 是 | 主要联系人 |
| 联系方式 | string | 否 | 手机、电话、微信或邮箱 |
| 来源 | enum | 是 | 手动录入、官网咨询、活动、转介绍、其他 |
| 备注 | text | 否 | 初始线索背景 |
| 下次联系时间 | datetime | 否 | 新建时可选，首次跟进后必填 |

列表字段：

- 客户名。
- 联系人。
- 来源。
- 当前状态。
- 归属销售。
- 最近跟进时间。
- 下次联系时间。
- 逾期状态。
- 创建时间。

能力：

- 新建线索，自动归属当前销售。
- 编辑客户名、联系人、来源、备注等基础信息。
- 按状态筛选。
- 按下次联系时间排序。
- 搜索客户名、联系人、备注。
- 查看线索详情。
- 主管支持按销售人筛选。
- 按来源筛选放入 S2+。

### 6.3 S1 线索详情

页面内容：

- 基础信息：客户名、联系人、联系方式、来源、备注。
- 状态信息：当前状态、归属销售、创建时间、最近跟进时间、下次联系时间。
- 跟进时间线：按时间倒序展示所有跟进记录。
- 状态变更记录：展示状态变更时间和操作人。
- 操作区：新增跟进、更新状态。

能力：

- 展示线索基础信息。
- 展示当前状态和关键时间。
- 展示跟进记录时间线。
- 新增跟进记录。
- 按状态机更新状态。
- 状态变更写入历史记录。
- AI 跟进建议放入 S2+。

### 6.4 S1 跟进记录

字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 沟通方式 | enum | 是 | 电话、微信、拜访、邮件 |
| 沟通摘要 | text | 是 | 本次沟通内容 |
| 下次联系时间 | datetime | 是 | 提醒和逾期判定依据 |
| 创建人 | system | 是 | 当前登录用户 |
| 创建时间 | system | 是 | 当前提交时间 |

写入规则：

- 沟通方式、沟通摘要、下次联系时间必填。
- 新增记录后更新线索最近跟进时间。
- 新增记录后更新线索下次联系时间。
- 跟进记录按时间倒序展示。
- 窄屏下可完成新增跟进记录；完整移动端体验放入 S2+。
- 已成交、已丢失线索不可继续新增下次提醒。

### 6.5 S1 提醒与逾期机制

规则：

- 今日待联系：下次联系日期等于当前日期。
- 即将到期：下次联系时间在未来 24 小时内，且未成交、未丢失。S1 仅在主管风险看板展示。
- 已逾期：下次联系时间早于当前时间，且未成交、未丢失。
- 逾期天数：当前日期减去下次联系日期，向下取整，最小为 1 天。

实现方式：

- S1 不强依赖定时任务生成待办表，可通过查询 `leads.next_follow_up_at` 动态计算今日待联系、即将到期和逾期。
- 如果后续需要站内通知或外部推送，再引入定时任务和通知表。
- 看板统计应统一复用同一套提醒与逾期判定逻辑，避免销售首页和主管看板口径不一致。

### 6.6 S1 主管风险看板

S1 主管看板只解决“谁需要尽快跟进”，不做完整经营分析。

- 展示团队今日待联系线索总数。
- 展示团队即将到期线索总数。
- 展示团队逾期线索总数。
- 按销售人分组展示今日待联系线索。
- 按销售人分组展示即将到期线索。
- 按销售人分组展示逾期线索。
- 每条线索展示客户名、状态、下次联系时间、距到期时间或逾期天数、最近跟进摘要。
- 支持按销售人筛选。
- 支持按到期状态筛选。
- 支持按逾期天数排序。

S2+ 主管看板增强：

- 展示各状态线索数量。
- 展示状态间转化率。
- 支持近 7 天、近 30 天筛选。
- 展示近 7 天每位销售新增线索数。
- 展示近 7 天每位销售跟进记录数。
- 展示近 30 天新增线索数和跟进记录数。

### 6.7 S2+ 老板看板

老板看板强调公司级过程数据，不强调操作。

能力：

- 公司全部线索状态分布。
- 公司转化漏斗。
- 近 7 天和近 30 天新增线索数。
- 近 7 天和近 30 天跟进记录数。
- 支持按团队或主管筛选。

### 6.8 S2+ AI 跟进建议

输入数据：

- 客户名。
- 来源。
- 当前状态。
- 备注。
- 全部跟进记录摘要。
- 最近一次跟进时间。
- 下次联系时间。

输出内容：

| 输出项 | 说明 |
| --- | --- |
| 沟通时机 | 建议何时联系客户 |
| 切入话题 | 建议本次沟通从什么问题或价值点开始 |
| 准备材料 | 建议销售提前准备的资料 |
| 风险提示 | 提醒可能存在的阻碍或客户顾虑 |

降级策略：

- 跟进记录不足时，返回基于当前状态的通用建议。
- 大模型调用失败时，展示“暂时无法生成建议”，核心页面继续可用。
- AI 建议仅供复制参考，不自动修改线索状态或跟进记录。

## 9. S1 权限与数据隔离

### 9.1 S1 权限矩阵

| 功能 | 销售 | 销售主管 |
| --- | --- | --- |
| 查看本人线索 | 是 | 是 |
| 查看团队线索 | 否 | 是 |
| 新建线索 | 是 | 是 |
| 编辑本人线索 | 是 | 是 |
| 新增跟进记录 | 是 | 是 |
| 更新线索状态 | 是 | 是 |
| 查看主管风险看板 | 否 | 是 |

老板角色、公司级明细和公司级看板权限放入 S2+。

### 9.2 数据范围

- 销售：只能访问 `owner_id = 当前用户 ID` 的线索。
- 销售主管：可访问 `team_id = 当前主管团队 ID` 的线索。
- 老板：S2+ 可访问全公司线索和汇总数据。

### 9.3 S2+ 后端鉴权规划

- S1 前端隐藏入口只作为体验优化，不作为真实安全边界。
- 所有列表查询必须在后端追加数据范围条件。
- 所有详情查询必须校验当前用户是否有权访问该线索。
- 所有写操作必须同时校验功能权限和数据权限。
- 状态变更、跟进记录新增必须写入操作人和时间。

## 10. 非功能设计

### 10.1 S1 本地可运行性

- 提供一条本地启动命令，启动后可在浏览器访问 UI。
- 本地环境内置或初始化演示数据，至少包含 2 个销售和 1 个主管。
- 本地环境支持演示角色切换，便于走通销售和主管两条视角。
- 本地启动失败时，命令行应输出可定位的错误信息。

### 10.2 性能

- 支持约 100 人并发使用。
- 主要页面响应时间小于 2 秒。
- 常规筛选、搜索响应时间小于 2 秒。
- S1 主管风险看板只加载当前未终态线索，避免一次性聚合过大范围。
- 今日待联系和逾期查询依赖 `next_follow_up_at` 索引。

### 10.3 可用性

- 销售从首页进入线索详情并新增跟进，应在 3 步内完成。
- 跟进记录表单只保留沟通方式、沟通摘要、下次联系时间等必要字段。
- 逾期状态醒目但克制，避免大面积强警示色。
- 表单错误提示靠近对应字段展示。

### 10.4 窄屏基础可用

- S1 核心页面在窄屏下不出现关键按钮不可见或表单无法提交的问题。
- 完整移动端导航、手势优化和专用快速跟进页面放入 S2+。
- 主要按钮点击区域不小于 44px。

### 10.5 安全

- 后端接口必须基于用户角色和组织关系校验数据权限。
- 联系方式等敏感字段可按角色控制展示范围。
- 状态变更必须写入状态日志。
- AI 调用放入 S2+；启用时只传入生成建议所需的最小上下文。

### 10.6 可靠性

- 新增跟进记录和更新线索最近跟进时间、下次联系时间必须在同一事务内完成。
- 状态变更和状态日志写入必须在同一事务内完成。
- S2+ AI 建议生成失败时，不影响线索详情和跟进记录核心功能。
- 看板统计接口失败时，不影响线索列表和跟进核心链路。

## 11. 测试方案

### 11.1 S1 本地端到端验收

- 执行本地启动命令后，浏览器可访问系统首页。
- 用户可选择销售身份进入销售首页。
- 销售可新建一条线索，提交后在线索列表中可见。
- 销售可进入线索详情，新增跟进记录并设置下次联系时间。
- 提交跟进记录后，线索最近跟进时间和下次联系时间同步更新。
- 销售可将线索从新线索流转到已联系、有意向、已成交或已丢失。
- 丢失线索时必须填写丢失原因。
- 销售首页可展示今日待联系和本人逾期线索。
- 用户可切换主管身份，查看团队今日待联系、即将到期和逾期线索。
- 主管点击风险线索可进入详情页查看跟进记录。

### 11.2 S1 线索管理测试

- 销售可成功创建线索，系统自动归属当前销售。
- 销售只能看到自己的线索。
- 主管可看到所属团队线索。
- 线索列表支持按状态筛选、按下次联系时间排序、按关键词搜索。

### 11.3 S1 跟进记录测试

- 销售可在线索详情新增跟进记录。
- 沟通方式、沟通摘要、下次联系时间缺失时无法提交。
- 提交跟进记录后，线索最近跟进时间和下次联系时间同步更新。
- 跟进记录按时间倒序展示。
- 窄屏下可完成新增跟进记录。

### 11.4 S1 状态流转测试

- 线索只能按定义的状态机流转。
- 丢失线索必须填写丢失原因。
- 每次状态变更均生成状态变更记录。
- 已成交、已丢失线索不出现在今日待联系和逾期列表。

### 11.5 S1 提醒与看板测试

- 销售首页准确展示今日待联系线索。
- 销售首页准确展示本人逾期线索和逾期天数。
- 同一条逾期线索不重复出现在今日待联系中。
- 主管看板按销售人分组展示团队今日待联系线索。
- 主管看板按销售人分组展示团队即将到期线索。
- 主管看板按销售人分组展示团队逾期线索。
- 主管看板展示团队各状态数量概览。

### 11.6 S1 权限测试

- 销售访问他人线索时返回无权限。
- 主管访问非团队线索时返回无权限。
- 前端入口隐藏后，直接调用接口仍必须被后端拦截。

### 11.7 S2+ 测试规划

- 老板看板展示公司级状态分布、漏斗和过程趋势。
- 主管看板展示状态间转化率和近 7 天/30 天销售活跃度。
- 线索详情页可触发 AI 跟进建议。
- AI 建议包含沟通时机、切入话题、准备材料和风险提示。
- 跟进记录不足时，系统可给出通用建议或明确提示信息。
- AI 失败时页面不报错，核心跟进功能可继续使用。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 销售不愿记录跟进 | 数据链路不完整 | 跟进记录只保留必要字段，移动端提供快速入口 |
| 下次联系时间填写不规范 | 提醒和逾期不准确 | 跟进记录中强制填写下次联系时间 |
| 权限边界不清晰 | 数据泄露风险 | S1 按销售、主管两层做演示隔离；S2+ 增加老板权限和后端接口鉴权测试 |
| 看板统计口径争议 | 管理层理解不一致 | 固化今日待联系、逾期、活跃度等指标定义 |
| AI 建议质量不稳定 | 销售信任度下降 | S2+ 作为辅助能力，不影响核心流程，建议可复制但不自动执行 |

## 14. 待确认问题

- 销售主管与销售的组织关系是否已经存在于公司账号体系中。
- 老板是否需要查看线索明细，还是只查看汇总数据。
- 联系方式字段是否需要拆分为手机、微信、邮箱。
- 丢失原因枚举是否需要按公司销售方法论定制。
- AI 跟进建议是否需要接入公司知识库或销售话术库。
