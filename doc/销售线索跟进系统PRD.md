## 2. 产品背景

企业在获客、分配、跟进、转化过程中通常会遇到以下问题：

- 线索来源分散，市场活动、官网表单、广告投放、渠道推荐、人工导入的数据缺乏统一沉淀。
- 销售跟进过程依赖个人习惯，容易出现遗漏、重复触达、跟进节奏不一致。
- 管理者难以及时判断线索质量、销售执行状态和转化瓶颈。
- 客户沟通记录散落在表格、聊天工具和个人笔记中，交接成本高。
- 无法基于数据持续优化线索评分、分配策略和销售资源投入。

销售线索跟进系统用于统一管理从线索进入到商机转化的完整流程，帮助团队提升响应速度、跟进质量和转化效率。

## 3. 产品目标

### 3.1 业务目标

- 提升新线索首次响应速度，将高意向线索的首次跟进控制在 15 分钟以内。
- 降低线索遗漏率，确保待跟进线索都有明确负责人和下一步计划。
- 提升线索到商机的转化率，为销售管理提供可追踪、可复盘的数据链路。
- 建立标准化销售跟进流程，减少新人上手成本和团队协作摩擦。

### 3.2 用户目标

- 销售人员可以快速看到今日需要处理的线索、优先级和建议动作。
- 销售主管可以实时掌握团队跟进进度、转化漏斗和异常线索。
- 市场人员可以追踪不同来源、活动、渠道的线索质量和转化贡献。
- 运营人员可以配置分配规则、标签体系、跟进模板和提醒策略。

## 4. 用户角色

| 角色 | 主要诉求 | 典型操作 |
| --- | --- | --- |
| 销售代表 | 高效跟进线索，记录沟通结果，推进转化 | 查看待办、拨打电话、记录跟进、创建商机 |
| 销售主管 | 管理团队执行，发现风险，优化分配 | 查看看板、分配线索、复盘漏斗、导出报表 |

## 5. 使用场景

### 5.1 新线索自动进入系统

客户通过官网表单提交咨询信息，系统自动创建线索，识别来源、行业、地区、需求关键词，并根据评分规则生成初始优先级。若命中自动分配规则，系统将线索分配给对应销售，同时创建首次跟进待办。

### 5.2 销售进行日常跟进

销售打开工作台，按优先级查看今日待跟进线索。进入线索详情后，可以查看客户基础信息、来源、沟通历史、标签、下一步动作，并记录本次跟进结果。若客户意向明确，销售可以将线索转换为商机。

### 5.3 主管复盘团队漏斗

销售主管查看团队看板，按人员、来源、阶段、时间范围分析线索量、响应时长、跟进次数、转化率和流失原因。对长时间未跟进、高价值未响应、即将超时的线索进行提醒或重新分配。

## 6. 产品范围

### 6.1 一期范围

- 线索创建、导入、编辑、去重、归档。
- 线索列表、筛选、搜索、排序和批量操作。
- 线索详情页，包含基础信息、跟进记录、时间线、待办和附件。
- 线索阶段管理：新线索、待跟进、跟进中、已转商机、已流失、无效。
- 线索分配：手动分配、按规则自动分配、回收公海。
- 跟进记录：电话、微信、邮件、会议、备注等类型。
- 待办提醒：首次跟进提醒、下次跟进提醒、超时提醒。
- 数据看板：线索总览、来源分析、人员跟进表现、转化漏斗。
- 角色权限：销售、主管、市场、运营、管理员。

### 6.2 暂不包含

- 内置呼叫中心完整能力。
- 复杂营销自动化旅程编排。
- 合同、回款、售后服务管理。
- AI 自动外呼。
- 多品牌多租户商业化计费能力。

## 7. 核心流程

### 7.1 线索流转流程

1. 线索进入：表单、导入、接口、手动创建。
2. 系统校验：字段完整性校验、手机号或邮箱去重。
3. 线索评分：根据来源、行业、规模、需求、行为生成优先级。
4. 线索分配：自动分配或进入公海池。
5. 销售跟进：记录沟通内容、更新阶段、设置下次跟进。
6. 结果处理：转商机、标记流失、标记无效或继续跟进。
7. 数据复盘：进入报表和漏斗分析。

### 7.2 首次响应流程

1. 系统创建新线索。
2. 根据 SLA 规则生成首次跟进截止时间。
3. 负责人收到站内通知。
4. 销售完成首次跟进并记录结果。
5. 若超时未处理，系统提醒销售和主管。

### 7.3 转商机流程

1. 销售在线索详情页点击“转为商机”。
2. 系统校验必填字段：客户名称、联系人、需求、预算、预计成交时间。
3. 销售填写商机金额、阶段、预计成交日期。
4. 系统创建商机，并保留原线索完整时间线。
5. 线索阶段变更为“已转商机”。

## 9. 非功能需求

### 9.1 性能

- 线索列表首屏加载时间不超过 2 秒。
- 常规筛选和搜索响应时间不超过 1.5 秒。
- 单次导入 10,000 条线索时，系统应异步处理并展示进度。
- 数据看板默认统计 90 天内数据，复杂报表允许异步生成。

### 9.2 可用性

- 核心操作路径不超过 3 步：查看线索、记录跟进、设置下次跟进。
- 表单必填项清晰标识，错误提示靠近字段展示。
- 支持移动端基础访问，销售可在手机上查看线索和新增跟进记录。

### 9.3 安全

- 手机号、邮箱等敏感字段按权限展示和导出。
- 所有导出操作记录审计日志。
- 用户只能查看自己或权限范围内的线索。
- 管理员可配置数据保留和删除策略。

### 9.4 可靠性

- 关键操作需要写入操作日志。
- 线索导入失败时提供错误明细和可下载失败清单。
- 系统异常时不得丢失已提交的跟进记录。

## 13. 关键指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 首次响应时长 | 线索创建到首次跟进的时间 | 高意向线索 15 分钟内 |
| 跟进完成率 | 已完成待办数 / 应完成待办数 | 90% 以上 |
| 超时线索率 | 超时未跟进线索数 / 待跟进线索数 | 5% 以下 |
| 线索转商机率 | 转商机线索数 / 有效线索数 | 持续提升 |
| 来源转化率 | 指定来源转商机数 / 指定来源有效线索数 | 用于渠道优化 |
| 公海回收率 | 回收线索数 / 分配线索数 | 用于评估分配质量 |

## 14. 交互与体验原则

- 首屏优先呈现“现在该处理什么”，减少销售判断成本。
- 高风险状态需要明确但克制，避免大面积警示色造成疲劳。
- 表单采用分组布局，基础信息、需求信息、跟进计划分区展示。
- 跟进记录入口应始终可见，支持快捷输入和模板化内容。
- 时间线以事件类型区分视觉层级，关键阶段变更需要突出。
- 移动端优先保障查看、拨号、记录跟进、设置提醒四个动作。

## 16. 验收标准

- 销售可以完成从查看线索到记录跟进再到设置下次跟进的完整闭环。
- 新线索可以按规则自动分配，失败时进入公海池。
- 主管可以查看团队线索状态、跟进情况和转化漏斗。
- 系统可以识别重复手机号或邮箱，并给出重复提示。
- 权限控制符合角色设计，非授权用户无法访问越权数据。
- 导入、导出、分配、转商机、删除等关键动作均有审计日志。
- 一期核心页面在桌面端和移动端均可正常使用。

## 17. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 线索字段定义不统一 | 导入失败、数据质量差 | 上线前统一字段字典和必填规则 |
| 销售不愿记录跟进 | 数据链路不完整 | 降低录入成本，提供模板和快捷操作 |
| 分配规则过于复杂 | 维护困难、分配不可解释 | 一期控制规则复杂度，保留命中日志 |
| 渠道数据不准确 | 来源分析失真 | 对接来源参数规范，导入时强制校验 |
| 权限边界不清晰 | 数据泄露风险 | 权限矩阵评审，关键接口增加鉴权测试 |
