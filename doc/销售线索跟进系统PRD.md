## 2. 背景与问题

### 2.1 业务背景

ToB 销售团队在日常线索跟进中，常通过表格、聊天记录或个人笔记管理客户信息。随着线索量和团队规模增长，这种方式会导致跟进节奏不稳定、线索遗漏、管理者难以及时发现风险。

本系统面向 100 人规模的 ToB 销售团队，提供从线索录入、跟进记录、状态流转到主管看板的轻量化闭环管理能力。

### 2.2 核心痛点

- 销售每天不知道最应该优先跟进哪些线索，容易遗漏或延迟。
- 主管无法实时发现哪些线索快过期、已逾期、由谁负责。
- 老板希望看到销售过程全貌，而不只是最终成交数据。
- 跟进记录分散，导致交接、复盘和管理成本高。
- 销售需要更具体的下一步建议，减少跟进时的判断成本。

### 2.3 产品定位

一个轻量但完整的销售线索跟进系统，重点解决两个问题：

- 销售视角：今天该跟谁。
- 主管视角：谁快过期了。

AI 跟进建议作为差异化亮点，在销售记录客户沟通历史后，帮助生成下一步沟通建议。

## 3. 产品目标

### 3.1 业务目标

| 目标 | 衡量方式 |
| --- | --- |
| 降低线索遗漏 | 逾期未跟进线索数下降 |
| 提升跟进执行率 | 今日待联系完成率提升 |
| 提升管理透明度 | 主管可按销售人查看逾期和状态分布 |
| 建立销售过程数据 | 所有状态变更和跟进记录可追溯 |
| 提升跟进质量 | 销售可参考 AI 建议进行下一步沟通 |

### 3.2 用户目标

- 销售可以快速录入线索、记录跟进、设置下次联系时间。
- 销售首页可以直接看到今日待联系线索。
- 主管可以看到团队逾期线索、转化漏斗和销售活跃度。
- 老板可以通过公司级视角查看整体转化和销售过程数据。

- 状态变更和跟进记录必须记录操作人和时间。
- 丢失线索必须填写丢失原因。

## 6. 线索状态机

### 6.1 状态定义

| 状态 | 含义 | 是否终态 |
| --- | --- | --- |
| 新线索 | 刚录入，尚未完成首次有效联系 | 否 |
| 已联系 | 已与客户发生一次有效沟通 | 否 |
| 有意向 | 客户表达明确需求或后续沟通意愿 | 否 |
| 已成交 | 线索完成成交 | 是 |
| 已丢失 | 确认不再继续跟进 | 是 |

### 6.2 状态流转

```text
新线索 -> 已联系 -> 有意向 -> 已成交
  |          |          |
  v          v          v
已丢失     已丢失     已丢失
```

### 6.3 状态流转规则

- 新线索可流转为：已联系、已丢失。
- 已联系可流转为：有意向、已丢失。
- 有意向可流转为：已成交、已丢失。
- 已成交和已丢失为终态，不进入待联系和逾期提醒。
- 每次状态变更必须记录：变更前状态、变更后状态、操作人、操作时间。
- 状态变更为已丢失时，必须填写丢失原因。

### 6.4 丢失原因枚举

- 无需求。
- 预算不足。
- 已选择竞争对手。
- 联系不上。
- 决策周期过长。
- 信息无效。
- 其他。

## 7. 核心用户流程

### 7.1 销售录入并跟进线索

1. 销售新建线索，填写客户名、联系人、来源、备注。
2. 系统自动归属当前销售。
3. 线索初始状态为新线索。
4. 销售填写首次跟进记录。
5. 系统要求填写下次联系时间。
6. 系统根据下次联系时间生成待联系提醒。

### 7.2 销售处理今日待联系

1. 销售进入首页。
2. 系统展示今日待联系线索，按下次联系时间排序。
3. 销售点击线索进入详情。
4. 销售查看基础信息、历史跟进记录和 AI 建议。
5. 销售新增跟进记录并设置下次联系时间。
6. 如需要，销售更新线索状态。

### 7.3 主管查看团队逾期

1. 主管进入主管看板。
2. 系统展示团队逾期线索总数和按销售分组的逾期清单。
3. 主管可查看每条线索逾期天数、当前状态、最近跟进摘要。
4. 主管可按销售人、状态、逾期天数筛选。
5. 主管线下或通过团队机制督促销售跟进。

### 7.4 老板查看公司销售过程

1. 老板进入公司视角看板。
2. 查看各状态线索数量和转化漏斗。
3. 查看近 7 天和近 30 天新增线索数、跟进记录数。
4. 按团队或销售主管查看整体表现。

### 8.6 提醒与逾期机制

#### 功能说明

系统基于下次联系时间自动生成待联系和逾期视图。

#### 规则定义

- 今日待联系：下次联系日期等于当前日期。
- 即将到期：下次联系时间在未来 24 小时内，且未成交、未丢失。
- 已逾期：下次联系时间早于当前时间，且未成交、未丢失。
- 逾期天数：当前日期减去下次联系日期，向下取整，最小为 1 天。

#### 需求明细

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| REMIND-01 | 销售首页展示今日待联系线索 | P0 |

| REMIND-03 | 主管看板展示团队逾期线索 | P0 |
| REMIND-04 | 逾期线索展示逾期天数 | P0 |
| REMIND-05 | 已成交和已丢失线索不参与提醒和逾期计算 | P0 |
| REMIND-06 | 支持按逾期天数排序 | P1 |

### 8.9 AI 跟进建议

#### 功能说明

AI 根据线索基础信息和全部沟通记录摘要，生成下一步跟进建议，帮助销售更快判断如何推进客户。

- 来源。

| 准备材料 | 建议销售提前准备的资料 |
| 风险提示 | 提醒可能存在的阻碍或客户顾虑 |

## 12. 关键指标

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 今日待联系数 | 下次联系日期为今天的未终态线索数 | 销售每日任务 |
| 今日完成跟进数 | 当日新增跟进记录数 | 衡量执行量 |
| 逾期线索数 | 下次联系时间已过且未终态的线索数 | 风险监控 |
| 逾期率 | 逾期线索数 / 未终态线索数 | 衡量管理健康度 |
| 状态转化率 | 下一状态数量 / 上一状态数量 | 衡量漏斗效率 |
| 新增线索数 | 指定周期内创建的线索数 | 衡量线索供给 |
| 跟进记录数 | 指定周期内新增跟进记录数 | 衡量销售活跃度 |

## 13. 非功能需求

### 13.1 性能

- 支持约 100 人并发使用。
- 主要页面响应时间小于 2 秒。
- 常规筛选、搜索响应时间小于 2 秒。
- 主管看板默认加载近 30 天数据，避免一次性聚合过大范围。

### 13.2 可用性

- 销售从首页进入线索详情并新增跟进，应在 3 步内完成。
- 跟进记录表单必须轻量，移动端可快速录入。
- 逾期状态应醒目但克制，避免大面积强警示色造成视觉疲劳。
- 表单错误提示应靠近对应字段展示。

### 13.3 移动端

- MVP 至少支持移动端查看今日待联系线索。
- MVP 支持移动端新增跟进记录。
- 移动端输入控件应适配触屏，主要按钮点击区域不小于 44px。

### 13.4 安全与数据隔离

- 后端接口必须基于用户角色和组织关系校验数据权限。
- 前端隐藏不可访问入口不能替代后端鉴权。
- 所有状态变更必须写入日志。
- 敏感字段如联系方式应根据权限控制展示范围。

### 13.5 可靠性

- 新增跟进记录和更新线索下次联系时间应作为一个事务处理。
- 状态变更和状态日志写入应保持一致。
- AI 建议生成失败时，不影响线索详情和跟进记录核心功能。

## 14. 验收标准

### 14.1 线索管理验收

- 销售可成功创建线索，系统自动归属当前销售。
- 销售只能看到自己的线索。
- 主管可看到所属团队线索。
- 老板可看到全公司线索。
- 线索列表支持按状态筛选、按下次联系时间排序、按关键词搜索。

### 14.2 跟进记录验收

- 销售可在线索详情新增跟进记录。
- 沟通方式、沟通摘要、下次联系时间缺失时无法提交。
- 提交跟进记录后，线索最近跟进时间和下次联系时间同步更新。
- 跟进记录按时间倒序展示。

### 14.3 状态流转验收

- 线索只能按定义的状态机流转。
- 丢失线索必须填写丢失原因。
- 每次状态变更均生成状态变更记录。
- 已成交、已丢失线索不出现在今日待联系和逾期列表。

### 14.4 提醒与看板验收

- 销售首页准确展示今日待联系线索。
- 销售首页准确展示本人逾期线索和逾期天数。
- 主管看板按销售人分组展示团队逾期线索。
- 主管看板展示各状态数量形成转化漏斗。
- 主管看板展示近 7 天和近 30 天销售活跃度。

### 14.5 AI 建议验收

- 线索详情页可触发 AI 跟进建议。
- AI 建议包含沟通时机、切入话题、准备材料。
- 跟进记录不足时，系统可给出通用建议或明确提示信息。
- AI 失败时页面不报错，核心跟进功能可继续使用。

## 16. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 销售不愿记录跟进 | 数据链路不完整 | 降低录入成本，跟进记录只保留必要字段 |
| 下次联系时间填写不规范 | 提醒和逾期不准确 | 跟进记录中强制填写下次联系时间 |
| 权限边界不清晰 | 数据泄露风险 | 按销售、主管、老板三层权限设计并增加接口鉴权测试 |
| 看板统计口径争议 | 管理层理解不一致 | 在 PRD 中固定今日待联系、逾期、活跃度等指标定义 |
| AI 建议质量不稳定 | 销售信任度下降 | V1.1 作为辅助能力，不影响核心流程，输出建议可复制但不自动执行 |

## 17. 待确认问题

- 销售主管与销售的组织关系是否已经存在于公司账号体系中。
- 老板是否需要查看线索明细，还是只查看汇总数据。
- 联系方式字段是否需要拆分为手机、微信、邮箱。
- 丢失原因枚举是否需要按公司销售方法论定制。
- AI 跟进建议是否需要接入公司知识库或销售话术库。
